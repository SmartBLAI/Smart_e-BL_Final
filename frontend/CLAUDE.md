## 프로젝트가 뭔지

전자 선하증권(B/L) 자동검증 플랫폼 "B/L Copilot"의 프론트엔드.
사용자는 수출기업·포워더(서류 작성)와 은행 심사역(검증 결과 확인).
백엔드 API는 아직 없어서 `src/mocks/shipment.fixture.ts`의 목데이터로 개발함.

## 개발자 정보 — 반드시 지켜주세요

이 프로젝트를 만드는 두 사람(김태훈·김민지)은 **코딩 경험이 거의 없는 초보**입니다.

- 코드를 한 번에 크게 만들지 말고, **작은 단위로 나눠서** 진행해주세요
- 코드를 준 다음, **한 줄씩 무엇을 하는지 초보자 눈높이로 설명**해주세요
- 새로운 용어(props, hook, state 등)가 나오면 그 자리에서 뜻을 풀어서 설명해주세요
- 한 파일이 너무 길어지면(200줄 이상) 먼저 나눌지 물어봐주세요

## 절대 지켜야 할 것 (변경 금지)

1. **타입은 `src/types/domain.ts`, 상수는 `src/constants/domain.ts`가 유일한 정의처입니다.**
   새 컴포넌트를 만들 때 이 파일들의 타입·상수·함수를 그대로 가져다 쓰고,
   여기 없는 타입이나 색상값을 임의로 새로 짓지 마세요. 필요하면 먼저 물어보세요.

2. **심각도 3단계** (`Critical` / `Warning` / `Info`) — 색상·정렬 순서는
   `constants/domain.ts`의 `SEVERITY`, `bySeverity`를 그대로 씁니다.
   심각도를 색으로만 구분하지 말고 아이콘·텍스트도 같이 표시합니다.

3. **선적 상태 6종** (`DRAFT → REVIEWING → VERIFIED → SUBMITTED → MONITORING → CLOSED`)
   임의로 상태를 추가하지 않습니다.

4. **신뢰도 4등급 임계값**은 `CONFIDENCE_THRESHOLD` 상수를 참조합니다. 하드코딩 금지.

5. **근거 없는 값은 표시하지 않습니다.** `bbox`가 없는 필드값은 화면에 추정해서
   채우지 말고 "출처 없음"으로 표시합니다 (`toConfidenceGrade` 함수 참고).

6. **자동 반영 금지.** 교정 제안(F2)이나 정정(F5)은 사용자가 명시적으로
   승인 버튼을 눌러야만 값이 바뀝니다. (단, 사용자가 직접 타이핑해서 값을
   고치는 건 이 규칙 대상이 아닙니다 — FieldRow의 인라인 편집 참고)

## 폴더 구조 규칙

- `src/components/` — **두 화면 이상**이 같이 쓰는 부품 (배지, 로딩 상태 등)
- `src/pages/S{번호}{이름}/` — 그 화면에서만 쓰는 부품. 예: `src/pages/S4Verdicts/`
- 새 컴포넌트를 만들 때 이 중 어디에 둘지 먼저 판단하고, 애매하면 물어보세요

**S3Draft 완전체**: 필드폼 + 뷰어 + 클릭연동 + 교정제안 + VerifyBar +

2026-08-19에 확정됨(아래 M-1 참고). ImpactPanel은 `?impact=1` URL

필드 수정 상태(`editedValues`)는 FieldForm이 아니라 그 부모인 S3Draft가
들고 있습니다(상태 끌어올리기). FieldRow에서 직접 타이핑해서 고치는 것과
SuggestionCard에서 교정 제안을 승인하는 것이 같은 상태를 공유해서, 값이

CONFIRMED로 친다"는 규칙(`shared/shipmentStats.ts`의 `effectiveGradeOf`)은
2026-08-19에 확정됨. 자세한 내용은 아래 M-2 참고.

## 확정된 결정 (M-1, 2026-08-19)

"검증 실행" 버튼은 `canTransitionToVerified`(`constants/domain.ts`) 게이트를
그대로 따르는 것으로 확정됨. 필수 확인 필드나 미해결 Critical 위반이 있으면
막히고, 막혔을 때는 "사유 기록 후 강제 실행"으로 우회할 수 있습니다 —
사유를 기록하는 즉시 `/verify`를 호출해 검증을 진행합니다(`VerifyBar.tsx`의
`handleOverrideSubmit`). 강제 실행 시 판정에서 제외되는 룰은 백엔드
`/verify`가 이미 `skipped`로 내려주므로 별도 DEFERRED 처리를 만들 필요는
없었습니다. 사유 기록은 지금은 콘솔 로그로만 남습니다 — 감사 로그를 받을
백엔드가 생기면 그쪽으로 보내도록 바꿀 것. 배경은
`M1_M2_팀확정요청.md` 참고.

## 확정된 결정 (M-2, 2026-08-19)

사용자가 필드 값을 직접 수정하거나 교정 제안을 승인하면 등급과 무관하게
`CONFIRMED`로 취급하는 것으로 확정됨 (`shared/shipmentStats.ts`의
`effectiveGradeOf` — FieldForm·FieldRow·VerifyBar가 전부 이 함수를 통해
이 규칙을 공유함). 근거: 사람이 직접 확인하고 고친 값이 AI 추출보다
신뢰할 만하다는 해석.

값 충돌 필드의 "후보 선택"은 직접 입력과 다르게 취급합니다 — 어느 후보를
고르든 충돌은 해소되지만(`conflict_flag: false`), 등급은 무조건 확정이
아니라 그 후보가 원래 갖고 있던 신뢰도를 그대로 따릅니다
(`shared/shipmentStats.ts`의 `resolveConflicts`). 배경은
`M1_M2_팀확정요청.md` 참고.
