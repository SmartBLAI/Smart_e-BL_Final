### 블랙박스 배터리 결과 (요약)

**aiService (28케이스)** — 인증(토큰 없음/오류 401, /health 면제), 정상 경로 8종(verify·rules·glossary·reality·normalize·report·share), 오입력(깨진 JSON 422, 타입 오류 422, 빈 bl 400, 200KB 필드, 인젝션 문자열, 빈/비PDF 파일 400) 모두 의도된 형태로 응답. **예외 2건은 §4의 P0-3, P1-4.**

**게이트웨이 (14케이스)** — 선적 CRUD·필드 저장·검증 저장·404/422 처리 정상. **예외: 업로드 500(P0-5), grade 오류 500(P1-6), 빈 파일 수용(P1-7), job 폴링 데드코드(P1-8).**

**브라우저 시나리오** — 랜딩→대시보드(게이트웨이 실데이터 연동)→초안 편집기(추출 필드 8건 표시)→검증 실행(xgboost-v1 실모델 응답, 위반/주의 카드 렌더)→선제 대응 리포트→PDF 내보내기(200 OK)까지 **전 구간 실동작 확인**. 목데이터 폴백 시 출처 배너 표시도 확인.

## 3. 강점 (심사 대응용)

- **aiService 테스트 커버리지가 두텁다**: 31개 테스트 파일 800+ 케이스 전체 통과. 압축폭탄 순서 방어, 매직바이트 검증, 업로드 크기 상한, CORS 화이트리스트, LLM 프롬프트 주입 방어(후보-인덱스 구조), serviceKey 마스킹 등 방어적 설계가 실제 구현돼 있음.
- **SQL 인젝션 없음**(전부 SQLAlchemy 파라미터 바인딩), 업로드 저장은 sha256 콘텐츠 주소라 경로 조작 불가.
- **프론트 기본기 양호**: `any` 캐스트·하드코딩 URL 없음, tsc/lint 클린, 목데이터 사용 시 출처 표시 규약 준수.
- **판정 근거 투명성**: 룰 카탈로그 버전+다이제스트가 모든 응답에 실리고, 위반마다 UCP600 조항 출처·수정 방법 제시.

## 5. 시연 전 체크리스트

1. **환경변수**: `DOCUMENT_STORAGE_ROOT`(로컬 기동 시), `AI_INTERNAL_TOKEN`, `REPORT_SHARE_SECRET`(미설정 시 재시작하면 공유 링크 전부 무효 — 발급 응답의 warning 필드로 확인 가능), `GEMINI_API_KEY`(미설정 시 리포트가 템플릿 요약으로 폴백 — 동작은 함).
2. **기동 순서**: postgres(healthy) → alembic upgrade → aiService → 게이트웨이 → frontend.
3. **`uv sync --extra ml`** 후 `pytest ai/defect_model/tests/` 재실행해 3건 실패 해소 확인.
4. **시연 데이터**: 대시보드에 빈 선적(출처 없음 카드)이 남아 있으면 목데이터 폴백 배너가 떠 산만함 — DB를 시연용 시드로 초기화.
5. **리허설에서 반드시 밟을 경로**: 새로고침·딥링크(P0-9), 공유 링크 열기(P0-4), 업로드 직후 다른 화면 조작(P0-2), EC2 시연이면 원격 브라우저 접속(P0-7).
