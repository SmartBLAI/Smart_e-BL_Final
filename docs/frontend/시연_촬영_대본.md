# F1~F4 시연 촬영 대본

대상: `docs/frontend/샘플_B_L_SHP-2026-0812-001.pdf` + `docs/frontend/샘플_L_C_MT700_SHP-2026-0812-001.txt`
촬영 화면: **http://localhost:8080** (nginx 배포본). 개발 서버(:5173)로 찍지 마세요 — 백엔드로 가는 경로가 달라서 배포본과 동작이 다릅니다.

## 0. 촬영 직전 점검 — 한 줄

```bash
./scripts/demo-check.sh
```

`✗` 가 하나라도 나오면 그 항목을 해결하기 전에는 촬영하지 마세요. 이 스크립트가 잡는 것은 전부 실제로 한 번씩 터졌던 문제입니다.

특히 두 가지:

**유령 프로세스** — 호스트에 `uvicorn api.main:app --port 5050` 이 남아 있으면 브라우저 요청이 컨테이너 대신 그쪽으로 샙니다. 배포된 코드가 아니라 그 프로세스가 뜰 때의 옛날 코드가 응답하므로, 화면에 나오는 값이 통째로 달라집니다. 실제로 이것 때문에 추출 결과가 전부 깨져 보였습니다.

**컨테이너 노후화** — `docker compose up -d --build` 는 이미지를 새로 만들 뿐 **컨테이너를 바꾸지 않습니다.** 반드시 `--force-recreate` 를 붙이세요.

```bash
docker compose up -d --build --force-recreate
```

### 컷 3 — F1 결과 · F2 표준 용어 교정 (90초)

S3 초안 편집기.

**3-1. 추출 결과 (30초)** — 왼쪽 필드 목록, 오른쪽 실제 업로드한 PDF.

> "선하증권에서 열세 개 항목을 뽑아 놓았습니다. 오른쪽은 방금 올린 원본입니다."

⚠ **필드를 클릭하지 마세요.** 실제 PDF 위에는 원문 위치 하이라이트가 그려지지 않고, 뷰어 아래 캡션에 `null · 1p` 또는 36자짜리 uuid가 그대로 찍힙니다. "값을 누르면 원본 위치를 보여준다"는 연출은 이번 촬영에서 뺍니다.

⚠ 화면 표기는 **13건**입니다(15건이 아닙니다). 추출은 15필드지만 운임은 화면에서 빼고, 선박명과 항차를 한 칸으로 합쳐서 보여줍니다.

**3-2. 확인이 필요한 필드 (20초)** — 그룹 머리말을 위에서 아래로 짚습니다.

화면은 항목 순서가 아니라 **등급순**으로 묶여 있습니다. 펼쳐져 있는 것은 맨 위 **필수 확인 4건**(B/L 번호·수하인·선적항·양륙항)뿐이고, **출처 없음 2건**과 **확인 권고 7건**은 접혀 있습니다. 두 그룹을 눌러서 펼치세요.

> "확신이 없는 값은 지어내지 않습니다. 확인이 필요한 항목은 등급을 나눠 표시하고, 발행일과 발행지는 이 서류에 아예 없어서 값 자리에 '출처 없음'이라고 적어 둡니다."

⚠ **"AI가 대부분 정확히 뽑았다"는 식으로 말하지 마세요.** 이 샘플은 확정 등급이 0건이라 모든 필드에 확인 표시가 붙어 있습니다. 화면과 대사가 정면으로 어긋납니다. 위 대사처럼 **"확신 없는 값을 밝힌다"** 는 쪽이 화면과 맞습니다.

**3-3. F2 표준 용어 교정 (40초)** — 제안 4건.

| 필드 | 현재 | 제안 | 근거 |
|---|---|---|---|
| 송하인 | `CO.,LTD` | `Co., Ltd.` | 상호 표기 정규화 규칙 |
| 수하인 | `GMBH` | `GmbH` | 상호 표기 정규화 규칙 |
| 총중량 | `KGS` | `KGM` | UN/ECE Rec 20 |
| 용적 | `CBM` | `MTQ` | UN/ECE Rec 20 |

> "표기를 국제 표준에 맞추자는 제안입니다. 근거가 되는 표준을 같이 보여주고, **자동으로 바꾸지 않습니다.** 사람이 승인해야 반영됩니다."

**선적항·양륙항에는 제안 카드가 없습니다.** 없는 게 정상입니다. 한때 `BUSAN → KRPUS`,
`HAMBURG → DEHAM` 을 제안했는데, 이걸 승인하면 다음 화면에서 없던 치명 하자 2건이
생겼습니다(D003·D004). **UN/LOCODE 는 선하증권 면에 쓰는 표기가 아닙니다** — 선사
양식의 Port of Loading 칸에는 항구명이 인쇄되고, 은행은 UCP 600 20조에 따라 그
항구명을 신용장 문언과 대조합니다. 코드는 EDI·세관 적하목록·DCSA 데이터 층의
형태입니다. 지금은 항구 제안이 항구명으로만 나가고(`PUSAN → BUSAN`), 이미 맞는
표기에는 카드를 띄우지 않습니다.

이 이야기를 굳이 카메라 앞에서 할 필요는 없습니다. 질문이 나오면 위 한 줄로 답하세요.

승인 시연은 **송하인·총중량·용적** 중에서 고르세요. 수하인은 필수 확인 등급이라
승인이 아니라 **값 확인함** 으로 넘어갑니다.

제안 4건 중 화면에 바로 보이는 것은 **수하인 1건**뿐입니다. 나머지 3건(송하인·
총중량·용적)은 접힌 "확인 권고" 그룹 안에 있으니, 3-2에서 그룹을 펼쳐 두면 네 건이
이어집니다.

제안 카드에는 근거 표준이 실제로 찍힙니다 — 송하인 카드의 **"출처: 상호 표기 정규화
규칙"**, 총중량 카드의 **"출처: UN/ECE Rec 20"** 을 짚으세요.

송하인 한두 건 승인 → 값이 바뀌는 것 확인 → 남은 필수 확인 필드를 **값 확인함** 으로 해소 → **검증 실행**.

필수 확인 4건을 전부 해소하기 전에는 **검증 실행 버튼이 비활성**입니다.

⚠ 승인 후에는 **반드시 이 화면에서 검증을 실행**하세요. 검증하지 않고 다른 화면으로 나갔다 오면 승인한 값이 사라집니다.

### 컷 4 — F3 제출 전 하자 예측 (70초)

S4 판정 화면. 화면 위쪽 요약은 **"위반 2건 · 주의 1건 · 참고 0건"** 으로 나옵니다.

> "신용장 조건으로 판단할 수 있는 규칙을 돌렸고, 세 건이 걸렸습니다."

⚠ **"평가 19건"은 화면에 없습니다.** 규칙 29개·평가 19개는 내레이션으로만 말할 수 있는 숫자입니다. "화면에 보시면 19개를…" 식으로 화면을 가리키지 마세요.

세 건을 하나씩 짚습니다.

| 규칙 | 심각도 | 화면에 나오는 것 | 화면에 **없는** 것 |
|---|---|---|---|
| D018 | 치명 | 선적일로부터 N일 경과, 제시기간 21일 + 조치 문구 | UCP 600 Art.14(c) |
| D022 | 치명 | 발행일 정보가 없습니다 | ISBP 821 E |
| D021 | 경고 | 발행지 정보가 없습니다 | ISBP 821 E |

⚠ **근거 조항은 이 화면에 표시되지 않습니다.** 카드에는 규칙 ID·설명·조치 문구만 나옵니다. "화면에 UCP 조항 근거가 함께 나옵니다"라고 말하면 거짓말이 됩니다. 조항을 언급하려면 **"이 판정은 UCP 600 제14조 c항을 근거로 합니다"** 처럼 화면을 가리키지 않고 설명하세요.

⚠ 카드의 **"고치러 가기" 링크를 누르지 마세요.** D018 카드는 링크 이름이 `on_board_date` 라는 영문 식별자로 그대로 찍히고, 눌러도 S3에서 아무 필드도 선택되지 않습니다.

경과 일수(선적일 2026-07-14 기준)는 **촬영하는 날마다 커집니다.** 대사에 숫자를 넣지 말고 화면에 찍힌 값을 읽으세요.

> "가장 중요한 건 첫 번째입니다. 선적은 신용장 기한 안에 했지만, 서류 제시가 21일을 넘겼습니다. 은행이 거절할 수 있는 사유이고, 사람이 눈으로 보고 잡기 어려운 종류입니다."

접혀 있는 **"검사하지 못한 항목 10건"** 을 펼쳐서 사유를 보여줍니다.

> "나머지 10개는 검사하지 않았다고 그대로 밝힙니다. 신용장에 해당 조건이 없어서 판단할 근거가 없기 때문입니다. 통과했다고 표시하지 않습니다."

### 컷 5 — F4 선제 대응 리포트 (60초)

S7 리포트. 화면 맨 위에 **"예상 하자 확률 100% (판정 보류 10건 제외)"** 와 모델명 `xgboost-v1` 이 나옵니다.

> "지금까지 찾은 내용을 은행에 보내기 전에 읽을 수 있는 형태로 정리합니다. 규칙 판정과 별개로, 학습 모델이 이 서류가 하자 판정을 받을 확률을 계산합니다."

⚠ 화면 숫자는 **0.998을 반올림한 100%** 입니다. "확실히 하자입니다"라고 단정하지 말고 **"모델이 계산한 확률"** 로 말하세요.

⚠ 리포트 본문은 **판정 카드와 미검사 목록의 재구성**입니다. 제시기한 D-day·요구서류 체크리스트·권고 사항은 백엔드 응답에는 있지만 **화면에는 없습니다.** 대사로 약속하지 마세요. 조치 문구도 이 화면에서는 빠집니다.

**PDF 내려받기** → 파일 열어서 보여주기. (버튼을 누르면 "PDF 생성 중…"으로 바뀌고 파일이 바로 저장됩니다.)

| "리포트를 링크로 공유할 수 있습니다" | 백엔드에만 있고 화면에 버튼이 없습니다 |
| "OCR로 읽었습니다" | 이 샘플은 텍스트 레이어가 있는 PDF라 OCR을 타지 않습니다. 스캔본일 때만 OCR입니다 |

## 6. 하자 0건 통과 사례 (선택 컷)

하자를 잡는 장면만 찍으면 "이 제품은 늘 빨간불을 켠다"로 읽힙니다. 정상 서류를
그냥 통과시키는 장면을 30초쯤 붙이면 그 오해가 사라집니다.

**기존 샘플로는 못 찍습니다.** `샘플_B_L_SHP-2026-0812-001.pdf` 는 "Place and Date
of Issue" 칸이 비어 있어 D021·D022 가 무조건 걸리고, 선적일 2026-07-14 는 제시기간
21일을 이미 넘겼습니다. 통과본은 따로 만듭니다.

```bash
python docs/frontend/시연_녹화/make-clean-sample.py
```

→ `docs/frontend/샘플_통과_B_L.pdf` · `docs/frontend/샘플_통과_L_C_MT700.txt`
(B/L `HLCUBUS2608777` · L/C `LC26082000777`)

⚠ **촬영 당일에 다시 만드세요.** 날짜를 실행일 기준으로 잡습니다(선적 3일 전 ·
선적기한 10일 뒤). 파일을 묵혀 두면 제시기간 21일이 지나면서 같은 파일이 하자로
바뀝니다. 그래서 이 두 파일은 저장소에 고정된 정답이 아니라 **매번 만들어 쓰는
소모품**입니다.

| 화면 | 화면에 찍히는 값 | 서버 실제 값 |
|---|---|---|
| S3 추출 | **추출 필드 13건** (필수 확인 2 · 확인 권고 8) | 15 필드 · 완성도 0.93 |
| S4 판정 | **위반 0건 · 주의 0건 · 참고 0건** + 미검사 8건 | 평가 21 / 미검사 8 |
| S7 리포트 | **예상 하자 확률 8%** · `xgboost-v1` | 0.077 |

하자 사례(평가 19)보다 평가 규칙이 2건 많습니다. 발행지·발행일이 채워지면서
D021·D022 가 미검사에서 통과로 넘어온 것입니다.

🚨 **"전부 검사했습니다"라고 말하면 안 됩니다.** 미검사 8건은 이 서류가 부실해서가
아니라 MT700 파서가 수하인·통지처·인코텀즈·중량·용적·운임을 L/C 쪽에서 아예 안
채우기 때문입니다 — 어떤 서류를 넣어도 이 8건은 남습니다. 화면에서 "검사하지 못한
항목 8건"을 펼쳐서 사유를 보여주고 **"비교 대상이 L/C에 없어 판단을 보류한 항목"**
이라고 설명하세요. 보류를 통과로 포장하지 않는 것이 이 컷의 신뢰도입니다.

항구 제안 함정은 이 사례에도, 하자 사례에도 더는 없습니다 (§3-3 참고).

자동 녹화:

```bash
CASE=clean PW=... node docs/frontend/시연_녹화/record-demo.mjs   # → F1-F4_시연_통과.webm
```
